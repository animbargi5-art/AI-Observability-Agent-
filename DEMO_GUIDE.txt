TattvaAI Demo Guide
==================

Complete step-by-step guide to run and demonstrate TattvaAI locally


Prerequisites
=============

Before starting, ensure you have the following installed:

Required Software:
- Docker Desktop (latest version)
- Git (for cloning the repository)
- Web Browser (Chrome, Firefox, Safari, Edge)

System Requirements:
- RAM: Minimum 8GB (16GB recommended)
- Storage: 5GB free space
- OS: Windows 10/11, macOS 10.15+, or Linux Ubuntu 18.04+

Verify Installation:
# Check Docker
docker --version
docker-compose --version

# Check Git
git --version


Quick Start (5 Minutes)
=======================

Step 1: Clone the Repository
git clone https://github.com/animbargi5-art/AI-Observability-Agent-.git TattvaAI
cd TattvaAI

Step 2: Start TattvaAI
docker-compose up --build -d

Expected time: 2-3 minutes for initial build

Step 3: Verify Services
# Check all services are running
docker-compose ps

# Test backend health
curl http://localhost:8000/health

Step 4: Access TattvaAI
Open your browser and navigate to:
- TattvaAI Dashboard: http://localhost:3001
- Backend API: http://localhost:8000
- API Documentation: http://localhost:8000/docs


Demo Walkthrough
================

1. Dashboard Overview
Navigate to: http://localhost:3001

What You'll See:
- Statistics Cards: Total investigations, severity breakdown, confidence metrics
- Recent Investigations: Latest AI-powered incident analyses
- Quick Actions: Start new investigation button
- System Status: Real-time health indicators

Demo Points:
✓ Modern, clean interface  
✓ Real-time statistics  
✓ Professional dashboard layout  
✓ Responsive design  

2. Start an Investigation
Action: Click "Start Investigation" button

What Happens:
1. AI Coordinator receives incident report
2. 6 specialized agents analyze different aspects:
   - Trace Agent: Analyzes distributed traces
   - Logs Agent: Processes error logs
   - Metrics Agent: Evaluates system metrics
   - Dependency Agent: Maps service failures
   - Alert Agent: Correlates alerts
   - Historical Agent: Matches past patterns

Expected Results:
- Investigation completes in 10-30 seconds
- Root cause identified with confidence score
- Evidence-based reasoning provided
- Actionable recommendations generated

3. Investigation Results
Navigate to: Investigation details page

Key Features to Highlight:

Evidence Panel:
- Traces: Latency spikes and error patterns
- Logs: Critical error messages and frequency  
- Metrics: Performance degradation indicators
- Alerts: Correlated system alerts

Root Cause Analysis:
- Primary Cause: Most likely root cause
- Confidence Score: AI certainty (0-100%)
- Supporting Evidence: Links to specific telemetry
- Impact Assessment: Affected services and users

Recommendations:
- Immediate Actions: Quick fixes to try now
- Short-term Solutions: Temporary mitigation steps
- Long-term Improvements: Prevent future occurrences

Timeline:
- Investigation Steps: What each agent analyzed
- Evidence Discovery: When key findings emerged
- Decision Points: How conclusions were reached

4. Reports & Analytics
Navigate to: Reports section

Available Reports:
- Severity Trends: Incident severity over time
- Investigation Performance: AI accuracy metrics
- Service Health: System reliability scores
- Resolution Times: MTTR improvements

5. Investigation History
Navigate to: History page

Features:
- Search & Filter: Find specific investigations
- Sort Options: By date, severity, confidence
- Status Tracking: Completed, in-progress, failed
- Export Options: Download investigation reports


Advanced Features Demo
======================

API Testing
Test the REST API directly:

# Start a new investigation
curl -X POST "http://localhost:8000/investigation/start?service_name=gateway"

# Get dashboard statistics
curl http://localhost:8000/dashboard/statistics

# Get recent investigations
curl http://localhost:8000/dashboard/recent

Microservices Architecture
View running services:
docker-compose ps

Expected Services:
- tattvaai-backend (port 8000) - Main AI engine
- tattvaai-frontend (port 3001) - React dashboard
- gateway (port 8011) - API gateway service
- inventory (port 8002) - Inventory microservice  
- payment (port 8004) - Payment processing service
- order (port 8003) - Order management service

Log Monitoring
View real-time logs:
# All services
docker-compose logs -f

# Specific service
docker-compose logs -f backend

# Investigation coordinator
docker-compose logs -f backend | grep "IncidentCoordinator"

Troubleshooting
===============

Common Issues:

Services Not Starting:
# Check Docker daemon
docker info

# Rebuild containers
docker-compose down
docker-compose up --build

Port Conflicts:
# Check port usage
netstat -an | grep :8000
netstat -an | grep :3001

# Stop conflicting services or change ports

Browser Issues:
# Clear browser cache
# Try incognito/private mode
# Check browser console for errors (F12)

Performance Issues:
# Check available resources
docker stats

# Increase Docker memory allocation
# Close unnecessary applications

Health Checks:
Verify all services:
# Backend health
curl http://localhost:8000/health
# Expected: {"status":"healthy"}

# Frontend accessibility  
curl http://localhost:3001
# Expected: HTML response

# API documentation
curl http://localhost:8000/docs
# Expected: OpenAPI docs

Log Analysis:
Check specific issues:
# Backend errors
docker-compose logs backend | grep -i error

# Frontend build issues
docker-compose logs frontend | grep -i error

# Database connection
docker-compose logs backend | grep -i database

Cleanup
=======

Stop All Services:
# Graceful shutdown
docker-compose down

# Remove containers and volumes
docker-compose down -v

# Clean up images (optional)
docker system prune -a

Resource Usage:
- Disk Space: ~2GB containers + 500MB images
- Memory Usage: ~4GB while running
- Network: Bridge network tattvaai_tattvaai-network
